Can monthly portfolio statements flow into the cloud and onto an executive dashboard, with no retyping?

A Python pipeline on Azure that turns an investment fund's monthly brokerage statements into a checked database.

Holdings, dividends and cash arrived each month as a PDF. Every figure had to be copied out by hand before anyone could analyse it.

The short answer

Yes, if it checks its own work. Each statement is read, converted at official exchange rates and loaded only if its totals match. 107 of 118 passed on their own, and the other 11 were caught for review. The loaded data then feeds an executive dashboard: value trend, asset mix and checks in one view.

  • No more re-keying. One upload per statement replaces copying figures out by hand.
  • Every number is traceable. Each figure links back to its source PDF and the exchange rate used.
  • Exceptions surface. Anything that doesn't reconcile is flagged, never loaded silently.

My role

I designed and built the pipeline end to end, from the PDF extraction to the Azure deployment.

Design decisions

  • From SQLite to Azure SQL. Testing showed the storage attached to a serverless function app does not reliably keep a database file between runs, so the data moved to Azure SQL with a one-time migration of the history.
  • Secrets stay out of the code. Connection details live in environment settings, and the public repository ships only placeholders.

Known gaps

Reinvested-dividend amounts are left blank and flagged until reinvestment price and share fields are added, a limit agreed with the team lead for the first version. Extraction depends on the broker's current layout, and the totals check is what catches a change.
